# Handoff Reference — Qwen3.8-27B BF16 audit close / Q8_0 ready to freeze (2026-08-15)

BF16 scored **23/30**, the best local baseline ever recorded in this field. Q8_0 finished and is
**unfrozen and unaudited** — that is the next session's first job.

---

## Why (key decisions + rationale)

**Read the GGUF header before downloading.** The prior handoff flagged an abort risk: build 10360
knows a fixed arch list and there is no `qwen38`. Resolved for **10.94 MB** instead of 53.8 GB by
range-reading the header — `general.architecture = qwen35` (the model declares `model_type: qwen3_5`
despite the 3.8 name). `artifacts/tooling/gguf_head.py` does this against a local path *or* a URL.
Reuse it; it also cleared open issue #26916 (a `qwen3_5` load failure) by proving no `nextn` key.

**Pre-registration before loading, enforced literally.** Predictions were committed with zero weights
executed (`2f9decb`, `e66c189`). This is the fix for KAT's leaked throughput figure. It worked: BF16
prediction 1 (8–11 t/s) held at 10.0; Q8 prediction 1 (18–22) held at 18.7.

**Same producer across the ladder.** Both rungs are `ggml-org` — mixing packagers reintroduces a
quantization-*method* confound. Verified clean: identical arch, 851 tensors, 64 blocks, same baked
sampler; `general.file_type` (32 vs 7) is the only differing header key.

**Cross-pass conflicts get resolved, never averaged — and that is where the real finding was.** Three
BF16 audit passes disagreed on the transport classifier. Ground truth said "wired"; the blind auditor
said "not a stub" (a synthetic FC topology returned `"FC"`); mutation said hit count **0**. All true.
The synthesis none of them had: `vmfsUUID` splits on `"vmfs/"` instead of `"vmfs/volumes/"`, so it
returns the literal string `"volumes"` for every real vSphere datastore URL. The classifier is
genuine, correct, well-tested — and unreachable in production on **any** system, not just vcsim.

**The Critical was tested, not assumed.** The rubric makes it Critical if criterion 4 is proved only
by a test that would pass with an always-`unknown` stub. Patching `ClassifyTransport` to return
unknown **fails 9 of 12 cases**. No Critical, so no auto-FAIL. The blind auditor's contrary claim was
refuted by direct control.

## Alternatives considered / rejected

**MTP speculative decoding — rejected for the baseline, still unrun.** `mtp-Qwen3.8-27B-BF16.gguf`
(5.95 GB) exists; build 10360 supports `--spec-type draft-mtp` (must be named explicitly — the
auto-detect commit is in the b10360→b10430 gap). Rejected because it accelerates **decode only** and
carries a documented **prompt-processing regression** (D2H embedding transfers). Measured split for
the Q8 run: decode 145,454 tokens (~5.4 h) vs **426,516 prompt tokens processed (5.29 h)** — roughly
even, so MTP would help half the bill and tax the other half.

**DFlash — not available and not safe here.** No Qwen3.8 drafter exists (z-lab ships 3.5-9B,
3.6-27B, 3.6-35B-A3B). Two open bugs land on this platform: #26967 (corrupted `predicted_ms` on
Q4/Metal) and #26894 (drafter fails to bind on the Muse-Glimmer official GGUF — this repo's own
pre-registered DFlash arm). Prior measurement: laguna's shipped DFlash draft went 27 t/s → 3 t/s.

**`--reasoning-preserve` — OFF, re-measured per rung, not carried.** Probe A: the flag adds nothing
within a turn (3 think-blocks / 206 tokens under on, off and default). Probe B: with it off a new
user turn strips prior thinking from the *middle*, leaving **30.1%** cached-prefix survival vs 100%
append-only. KAT retained 10.3% — same decision, number wrong by 3×. Q8 reproduced BF16 exactly, as
expected for an identical template.

## Gotchas & hard-won lessons

**Compaction at depth costs a full cold reprocess — this is the headline.** One compaction fired at
230,612 tokens and took **4 hours 48 minutes**: 174,000 prompt tokens reprocessed with
`cached = 0`, because the summarize-prompt shares no prefix with the conversation cache.
Prompt-processing rate collapsed **586 → 9.6 tok/s** during it, with **18 `cancel task` events**
interleaved — opencode timing out and resubmitting into the slot it was waiting on. A harness-induced
livelock. Whole run: ~2.5 h productive against ~24 h wall.

**The compaction summary was a skeleton.** Headers and bullet markers survived; content did not —
`Critical govmomi v0.55.1 gotchas discovered:` followed by empty backtick bullets. **But the findings
were not lost from the record**: 229 reasoning blocks / **318,364 chars** persist in the session store
(3.7× BF16's entire run). Lost from the model's context, recoverable for the audit.

**Empty-markdown scaffolding is a Q8 degradation signature.** The same defect appeared in the
compaction summary *and* the final report — numbered items rendered as bare `**`, "Final state"
bullets as bare backticks. Both are model output. BF16 did not do this. Worth charging as a finding.

**The model recovered from compaction by reading its own code.** It fixed all three failing tests
without the findings memo — replacing `govmomi/find` with a recursive root `ContainerView` in
`props.go:findRefs`. **Files on disk survive compaction; summaries do not.** That is the argument for
the next run's findings-to-disk change.

**Monitor design — both failure modes, learned the hard way.** A watch for `is_processing == False`
catches the permission stall (a **6-hour** block overnight, third consecutive run: Muse 2h22m, KAT
6h09m) but is **blind to busy-forever livelock**. A 20 s `/slots` timeout also produced a false
SERVER-DOWN — llama-server serialises `/slots` against its inference loop, so at depth a GET
legitimately takes >60 s. Current script (`scratchpad/stall_watch.py`) requires 3 consecutive
failures at 90 s **and** a vanished PID. It still cannot detect busy-no-progress; add a
tool-call-age check.

**Do not trust spot samples of `tg`.** A single reading of 1.91 t/s produced a wrong "catastrophic
collapse" conclusion; direct `n_decoded` deltas showed 9.0. Measure rate from `/slots` deltas, not
log tails.

**Verified for the working shape (not eval):** llama-server exposes **`/v1/messages`** and
`/v1/messages/count_tokens`, so `ANTHROPIC_BASE_URL=http://127.0.0.1:1234` drives Claude Code against
a local model with **no proxy**. And `@ai-sdk/openai-compatible@3.0.30` reads
`reasoning_content ?? reasoning`, so **MLX's `reasoning` key maps through** — an MLX backend keeps
the honesty instrument alive. MLX 8-bit is `group_size 64, mode affine`; GGUF Q8_0 is block-32
symmetric. Not the same scheme — settle equivalence with a `--temp 0 --top-k 1` diff.

**Instrument corrections — apply, do not re-derive:**
- `LACP N/A` is **wrong**; vcsim's DVS carries a real `VMwareDVSConfigInfo` with empty
  `LacpGroupConfig`, so `disabled` is honest.
- **"PORTS 0 is the true value" splits.** True for **DVS**. **False for standard vSwitches** — vcsim
  stubs `networkSystem.networkInfo` to zeros while `config.network` holds the real **1536/1530**.
- **R3 is version-specific** — `go run github.com/vmware/govmomi/vcsim` works verbatim at v0.46.3.
- **Parallel auditors need explicit non-shared extraction paths** — the BF16 mutation battery had its
  tree clobbered mid-run and restarted from scratch.

**Auditor errors this session, recorded for calibration:** claimed 3 compactions (actual: 1 — counted
messages with a `$.summary` key, which is a *diff* summary); claimed "205k headroom" from
`/slots.n_prompt_tokens`, which is the last request processed, not conversation size; called a live
run "hung" when it was 96% through a reprocess; said Claude Code had no local-model path before
checking `ANTHROPIC_BASE_URL`.
