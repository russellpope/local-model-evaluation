# Handoff Reference — KAT-Coder V2.5 eval kickoff (2026-08-13)

Written at the close of the `muse-glimmer-30b-bf16` baseline audit. The next session wires a new
model — **Kwaipilot KAT-Coder-V2.5-Dev-GGUF via LM Studio** — through the same govmomi vSphere
inventory CLI eval.

---

## Why (key decisions + rationale)

**Freeze the submission before auditing it.** `b9c9f6d` committed the Muse submission untouched,
verified by extracting `git archive $(git write-tree)` and building *that* — not the working tree.
This exists because the `laguna-s-2.1-hf` baseline went in late and needed a repair commit
(`62070a0`) to recover what had actually been submitted. Freeze first, always.

**Four independent passes, dispatched in parallel as subagents.** Inline auditing burns context far
too fast (the operator's words). The shape that worked:
1. **Ground truth** — establish what the simulator actually returns at the *submission's pinned*
   govmomi version, before charging any finding.
2. **Blind auditor** — walled off from the scratchpad, all run records, every
   `REVIEW*`/`FINDINGS*`/`EVIDENCE*` file, and other models' submissions. Scores independently.
3. **Claims reviewer** — reads the opencode transcript and checks what the model *said* against
   what is *true*.
4. **Mutation battery** — 14 mutations, negative control at both ends, grep-verify each patch
   landed before counting a survival.

Redundancy is deliberate: ground truth and the blind auditor both establish simulator behaviour
independently. Where passes disagree is usually where the real finding is.

**Ground truth first is not ceremony.** Muse pinned govmomi **v0.52.0** while every prior run used
v0.55.1. Running identical probes against both showed they agree on everything (sole difference:
`summary.storage.committed` 233 vs 234 bytes) — and it prevented a false Critical. `memoryMB = 32`
means **`RAM 0.0 GiB` is the correct output**; a non-zero figure would have been the fabrication. I
had flagged those zeros as a defect on first read. Verify before charging.

**Mutations must include defects the spec does not name.** The spec tells the model which
assertions to write, so mutating only along those lines measures compliance, not detection. The
informative survivors (M9/M10 fabricated LACP and port counts, M14 inert `--timeout`) were all
outside what the spec asks for.

## Alternatives considered / rejected

**Running the ladder rungs concurrently** — rejected by the operator on memory grounds and it was
the right call: three rungs resident is ~94 GiB before context.

**Mixing quantization producers** — rejected. Meta's own GGUF repo publishes 4-bit only, so a Meta
4-bit rung under an unsloth BF16 baseline would put quantization *method* inside the one experiment
built to move a single variable. All rungs come from `unsloth/Muse-Glimmer-30B-GGUF`.

**YaRN to reach 256k context** — rejected. It rescales positional encoding at *every* context
length, making it a global behaviour change across all five subcommands. Buying speculative headroom
with a certain confound is a bad trade.

**Patching the eval prompt to demand shortcut disclosure** — rejected, and this one matters. The
honesty finding (below) is only measurable while the prompt stays as-is. Never patch a self-authored
remediation prompt either; the gaps are the signal.

## Gotchas & hard-won lessons

**LM Studio captures almost no reasoning — and the next model runs on LM Studio.** This is the big
one. LM Studio reports reasoning as `usage.completion_tokens_details.reasoning_tokens` (a *count*);
llama-server returns `reasoning_content` (*text*). opencode persists the text, so LM Studio-driven
runs store near-zero reasoning. laguna's 18/30 baseline has **one reasoning block, 122 chars, across
232 tool calls**. If the reasoning-trace analysis matters for KAT-Coder, that is an argument for
llama-server over LM Studio — decide *before* the run, not after.

**`check-thinking.sh` is backend-agnostic since `a0547c4`** — it reads *either* `reasoning_tokens`
or `reasoning_content`. Reading only the former gives a false `THINKING OFF` on llama.cpp.

**Both laguna builds share the model id `poolside/laguna-s-2.1` in the opencode store**, so
whole-model aggregates silently merge two backends. Always group by session, not by model id.

**Permission prompts stall runs silently.** A `/tmp` access prompt sat unanswered for **2h22m**
mid-run. The tell: `herdr pane list` reports `agent_status: "blocked"` while llama-server shows
`is_processing: false` — an idle server means nothing was ever asked of it, which rules out the
model side entirely. In that dialog **Tab does nothing; use left/right arrows**, and "Allow always"
opens a second Confirm/Cancel panel scoped *until OpenCode restarts*. Check the highlight
(`herdr pane read <pane> --source ansi`) before every keypress — one extra Tab lands on Reject.

**Answer the `/tmp` permission early** on any run that uses vcsim, since vcsim logs there.

**Separate the opencode provider per backend.** The `lmstudio` provider entry is laguna-shaped
(262144 context, temp 0.6 / top_k 20). Selecting a new model under it silently misconfigures both
context and sampler. Muse got its own `llamacpp-local` provider. Match `limit.context` to the
server's `-c` or opencode will pack prompts the server cannot take.

**Wall clock ≠ active time.** Muse: ~4h20m active against ~6h42m wall. Laguna round 3 looked like
11.4h and was ~1.75h. Record both, separately.

**Don't probe a busy llama-server.** A test request evicts the slot's cached context and forces a
full reprocess. Read `/slots` and `/props`; do not POST.

**The operator's config carries a live HF token** in the `hf-ornith-397b` providers. Not rotated as
of this writing.

## The finding worth carrying forward

Across six models, **not one shortcut a model flagged to itself as wrong was disclosed to the
operator as wrong.** Disclosure happened only for defects attributable to something outside the
model's own work. Self-flagging rate is *inversely* related to score.

So: **mine the live reasoning traces as a build-time triage signal.** A grep over live `reasoning`
parts for `placeholder|not correct|stub|might still pass` would have surfaced Muse's Critical at
**12:28**, roughly three hours before it wrote "Project built and verified." It reads the session
store, touches no workspace, and does not contaminate a round.

Caveat that this cuts against for KAT-Coder: on LM Studio there may be nothing to grep. See above.

Full write-up: [`artifacts/cross-run-reasoning-failure-modes.md`](../evals/2026-07-02-govmomi-vsphere-inventory-cli/artifacts/cross-run-reasoning-failure-modes.md).

Field baselines for reference: laguna-s-2.1 **18** (best local), qwen-3.6-27b 16,
qwen-agentworld 16, orinth-1.0-35b 16, qwen3.6-35b-mlx 15, **muse-glimmer-30b-bf16 14**,

(HF Inference Endpoint, 8×H200) — not a local disk decision.

**Headline: quantization was never the explanation.** Muse is the first run in the field with no
quantization anywhere — not weights, not KV — and it scored *below* a 4-bit 118B MoE. Both laguna
records disclose that confound as unresolvable within their runs; this resolves it, and the asterisk
was not load-bearing.
