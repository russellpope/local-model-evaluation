# Handoff Reference — Ornith 1.5 35B BF16 audit + a scoring-calibration defect (2026-08-20)

## Why this doc exists

`ornith-1.5-35b-a3b-bf16` audited to **12 / 30, FAIL**. That would rank 13th of 15 baselines —
below `qwen3-coder-next` (13) — for a submission that executed live against vcsim, ships zero
`t.Skip`, passes `-race`, caught 13 of 28 mutations, and found and fixed a real cobra bug
mid-run. The operator flagged the result as implausible. **He was right**, and the investigation
found an instrument defect that affects the whole field.

Two claims to keep separate:

- **The FAIL verdict is sound.** One Critical, independently found by all four auditors.
- **The 12/30 number is NOT comparable to this field's other scores** and must not be treated
  as one until the calibration question below is resolved.

## The calibration defect

**The rubric defines no score anchors.** `govmomi-cli-audit-prompt.md:233` says only
"dimension → score 1–5 → one-line justification". Nothing states what a 2 means versus a 3 or a
4:

```
$ grep -cniE 'excellent|adequate|poor|5 =|4 =|3 =|2 =|1 =' govmomi-cli-audit-prompt.md
0
```

Every auditor calibrates from scratch. Four independent auditors returned **2 on all six
dimensions** — a flatness that reads as a shared default after writing a long findings list, not
as six measurements.

### The comparison that proves it

Against `qwen3.8-27b-bf16` (23/30, the current best local baseline):

| Dimension | qwen3.8-27b-bf16 | ornith-1.5-35b-bf16 | Same evidence? |
|---|--:|--:|---|
| Security | **5** — "TLS verify default false, no credential leakage, gosec clean" | **2** | Ornith has identical hygiene, plus one env-var bug found by deeper probing |
| Concurrency | **5** — "Race-clean." | **2** | Ornith is also race-clean, no leaks, `Logout` on all paths; lost points to a timeout bug found via a delaying proxy |
| Performance | **3** — "fleet-wide `config.storageDevice`, per-DVS N+1" | **2** | The *same defect classes*, only measured (36× vs batched) |
| Quality | **4** — *"Held deliberately — mutation charges several survivors to the instrument, so the test gaps are not double-penalised"* | **2** | Opposite handling of the same evidence class |

Qwen's entire Concurrency justification was "Race-clean." Nobody probed whether *its* timeout was
plumbed. Ornith's timeout bug is real — but it is real because someone built a reverse proxy to
look for it.

### Depth asymmetry

- **qwen3.8-27b-bf16:** one blind pass + one synthesis pass (its record carries `Blind` and
  `Final` columns; blind was 4/4/5/3/5/4 = 25, adjusted to 23).
- **ornith-1.5-35b-bf16:** four parallel fresh-context auditors, each with a requirements-attack
  step, reverse-proxy timeout probes, SOAP-trace round-trip counting against a scaled vcsim, a
  counterfactual `ContainerView` baseline, and a 28-mutation battery.

More scrutiny found more defects. That is an instrument change, not a model regression.

## Resolution options (operator's call — do NOT pick unilaterally)

1. **Add score anchors to the rubric and re-score every run from its existing findings.** Most
   correct, most work. Preserves all recorded evidence; only the mapping changes.
2. **Re-score ornith-1.5 only, calibrated against qwen3.8's published mapping** (Security 5 for
   clean TLS + no leakage; Concurrency 5 for race-clean; Quality held rather than charging
   mutation survivors). Fast, restores comparability with the direct rival, leaves the rest of
   the field on the old scale.
3. **Record 12/30 with an explicit non-comparability flag** and re-audit `qwen3.8-27b-bf16` at
   the new depth to re-anchor the field. Most honest, most expensive.
4. **Split the ledger**: `score:` stays on the legacy scale, a new field carries deep-audit
   scores. Avoids retconning but forks the instrument.

Note: option 2 has a trap. If Ornith's Security/Concurrency are lifted to match qwen's
justifications, the env-prefix and timeout bugs go unrecorded in the score — both are genuine
and both would likely be found in qwen too if anyone looked. Prefer flagging over silently
lifting.

## What the audit actually established (independent of scoring)

**Critical — the tested transport classifier is dead code.** `transport.go:21 classifyTransport`
has genuine FC/iSCSI/NVMe/NFS branching and is the sole subject of the criterion-4 test (12
cases). It has **no production caller**. The live path is
`inventory.go:136 deriveTransport → :177 transportFromHost`, untested. Negative control:
replacing `deriveTransport`'s body with `return "unknown"` leaves `go test ./...` green. This is
the rubric §B cheat signature verbatim, found by all four auditors including the two not
assigned integrity.

Supporting Highs: `hostAdapterKey` type-switches on `*types.HostHostBusAdapter` while callers
pass `*HostFibreChannelHba`/`*HostInternetScsiHba` (embedding ≠ identity), so it always returns
`""` and the LUN→adapter join is permanently dead; production emits lowercase `fc`/`iscsi`
outside the spec's vocabulary; NVMe unreachable on the live path; `--timeout` created then
dropped (30s run under `--timeout 1s`); `AutomaticEnv` without `SetEnvPrefix` lets ambient
`$INSECURE`/`$URL`/`$PASSWORD` override the documented vars; multi-DC vCenter hard-fails; nested
DVS silently dropped.

Full detail: `ornith-1.5-35b-a3b-bf16/REVIEW.md`.

## Cross-pass disagreements — resolved, never averaged

- **Timeout.** Quality reported it working from a `--timeout 1ns` probe; at 1ns even *login*
  times out so the CLI errs and looks correct. Security proved it broken with a proxy that
  delays everything *except* login. Security is right; Quality's positive withdrawn.
- **pflag.** Quality called it a direct-dependency violation; Accuracy called deps clean.
  Accuracy is right per this repo's recorded instrument correction. Dismissed as auditor error.

## Auditor errors recorded against the auditor (driver's inline pass)

1. Claimed Ornith 1.0 "did not explore the source before writing code." **False** — 193
   `vim25/types` opens vs qwen3.8's 176. Inferred from an absent note. Retracted in
   `cross-run-reasoning-failure-modes.md` §5 and its corrections list.
2. Pre-registered that a `USED` column without a `UsedPorts` lookup would show the Ornith 1.0
   fabrication class. **Falsified** — `USED` is 1 and 0 against `PORTS` 1536, genuinely derived
   from `len(pg.Port)`. The tool-call marker measured lookup *style*, not knowledge.
3. Credited `distributed.go:15` ("the simulator does not implement `view.ContainerView.Retrieve`")
   as evidence of a real execution loop. **False** — two auditors independently ran
   `CreateContainerView` + `Retrieve` successfully against vcsim v0.55.1. It is a false
   justification for an N+1 design.

Pattern across all three: inferring from *absence* — a missing note, a zero in a marker, an
unverified comment. Absence is weak evidence. Execute before crediting.

## Rubric contradictions found by the requirements-attack (unresolved, operator's call)

- **RA-A** — spec unit-test 2 mandates `TYPE ∈ {…,unknown}`; rubric §B calls that exact test a
  Critical when everything is `unknown`. Does **not** change this verdict — criterion 4 fails on
  implementation grounds independently.
- **RA-B** — criterion 5's `used = total − available` is unsatisfiable per row:
  `NumPorts`/`NumPortsAvailable` live on the switch, and `DistributedVirtualPortgroup` has no
  available count at v0.55.1.
- **RA-C** — the spec states no performance requirement; the rubric grades N+1 at High. A
  submission can be spec-compliant and rubric-penalised. Perf was not rolled into the FAIL.
- **RA-D** — RAM specified as GB in one place, GiB/TiB at one decimal in another.
- **RA-E** — rubric C's "password never in a URL" is unachievable literally; `govmomi.NewClient`
  takes credentials in URL userinfo.
- **RA-F** — rubric E cannot discriminate on a spec that never requires concurrency; a green
  `-race` is a weak signal (zero goroutines in application code).
- **RA-G** — the spec's `go run github.com/vmware/govmomi/vcsim` is structurally impossible at
  v0.55.1. The model diagnosed this correctly and was credited.

## Run conditions

Sampler `temp 0.6 / top_p 0.95 / top_k 20 @ ctx 262144` — vendor setting for general tasks and
identical to every Ornith 1.0 run. ~5h20m wall clock, **2 compactions**, 29.1 t/s generation,
~210–227 t/s prompt eval, 69.9 GiB resident of 128.

**Compaction result worth keeping:** Ornith's compaction reprocessed 171,005 tokens in
**16m20s** (174 t/s prefill). Qwen3.8-27B Q8_0 reprocessed a near-identical 173,606 tokens in
**5h04m39s** (~10 t/s prefill) — 20.1% of a 25h12m run. Near-identical token counts, ~18×
prefill throughput difference. Not a controlled comparison (different model, quant, and backend)
but a strong signal that MoE prefill is where A3B pays most. The 35B Q8 rung will separate
precision from architecture on the same model.

## Gotchas learned this session

- **A wrong model pick is silent.** llama-server ignores the request's `model` field and answers
  from whatever it loaded; `--alias` only changes what `/v1/models` reports. All four rungs are
  selectable in opencode but only the running one is backed. Operator declined a preflight guard
  and asks to be told the live rung instead.
- **Do NOT pass `-v` to llama-server.** Rung 1 used it: ~377 log lines/sec, 142 MiB/hr. Default
  verbosity still shows slot lifecycle, prompt-done, timings and context shifts.
- **Count compactions only with `json_extract(data,'$.type')='compaction'`** on `part`. A
  message `$.summary` key is a diff summary and previously caused a 1→3 miscount.
- opencode session rows record the directory path *as it was at session time* — the `orinth` →
  `ornith` rename means old sessions match `%orinth%`, not `%ornith%`.
- **`sed -n "$((n-46)),..."`** with a computed negative offset fails with "illegal option"; guard
  the arithmetic.
- The `Bash` tool runs zsh; the operator's shell is fish. No `timeout` binary. `cd` does not
  persist between calls.
- vcsim is a **separate module** at v0.55.1 with `replace` directives, so `go run pkg@version`
  is rejected. Build it to a temp binary. `curl -k /sdk` returns 405 — use a TCP probe for
  readiness.
- vcsim does **not** populate `DVPort.Connectee`, so DVS `USED=0` is an honest degrade. But it
  *does* populate `NumPorts`/`NumPortsAvailable` (1536/1530) and standard-switch pnic uplinks —
  so `N/A` for a *standard* switch would be a finding, unlike for distributed.
