## The round-4 arm — this is the experiment

**New design: minimal-information prompting.** The operator is having the model author its round-4
prompt from **only** the score-detractors table and the auditor's "biggest detractors" prose — *no
hitlist, no `file:line` references, no prescriptive fix list, not even from the auditor.*

Rounds 1–3 all used a detailed instrument (`HITLIST-round2.md`, `HITLIST-round3.md`) with exact
`file:line` fixes. Round 4 removes that scaffolding entirely. **Do not write a hitlist for round 4.**
If asked to help, the correct answer is that supplying one destroys the arm.

**What it tests:** whether the model can derive *what to do* from *what went wrong*, rather than
executing a list. Rounds 1–3 established it executes well on anything it attempts; the open question
is whether it can prioritise unaided.

**Pre-registered prediction, recorded before the round runs** (in the run record's Remediate
section): the model's own diagnosis was *"the capability is there, the engagement just isn't"* —
framing the failure as choice. The competing hypothesis is structural: with `preserveThinking` off,
it wrote `RUN_EVIDENCE.md` in a single pass ~250 tool calls deep (context depth, not elapsed time --
the "11-hour" figure was corrected 2026-08-04 to ~1.75 h active), reconstructing
from a context that had stripped its own reasoning. **If round 4's self-report is accurate,
engagement was the constraint. If it is wrong again, the `preserveThinking` A/B becomes the next
experiment** — identical tree, identical instrument, one variable.

## Audit method (three passes — do not shortcut)

Every rescore used three independent verifications, and they repeatedly disagreed in useful ways:

1. **Blind reviewer** — fresh context, given only rubric + spec + workspace path. Explicitly
   forbidden from reading `REVIEW*`, `REMEDIATION*`, `HITLIST*`. Produces the conformance matrix.
2. **Claims/regression reviewer** — given the hitlist and the baseline diffs; reconciles
   `RUN_EVIDENCE.md` line-by-line and checks for regressions and relocated cheats.
3. **Orchestrator reproduction** — my own gates, coverage, targeted mutations.

**Why it matters:** in round 2 the two reviewers *appeared* to contradict each other on the
classifier. Both were right — one probed `classifyByScsiTopology` directly, entering *below* a
failing type assertion the other found. Reconciling that produced the round's decisive finding.

### Mutation testing is the load-bearing instrument

Coverage numbers mislead; mutations don't. Kill rates across the arc on independently designed
batteries: **r1 ~7%, r2 37.5%, r3 61–70%.**

Two rules learned the hard way:

- **Always design mutations the instrument did NOT name.** A suite can be rigged to detect the
  listed edits. Comparing named vs unnamed kill rates is how you tell (r3: 66.7% vs 60.7% — a
  six-point gap, so genuinely load-bearing).
- **Always run an unmutated negative control.** The r3 blind reviewer first reported **100%**,
  distrusted it, and found its *own* harness had excluded a directory, failing every mutant
  environmentally. Honest rate was 70%. Quote no mutation figure without this.

## Auditor instrument defects — recorded, not absorbed

These are **my** errors, and the record attributes them rather than charging the model:

1. **HITLIST-round2 §2.6 induced a spec regression.** It said "surface all five [error-swallowing
   sites]" without stating that the TYPE column must still degrade to `unknown`. The model surfaced
   them by returning errors — a defensible reading that broke criterion 7. Round 3's §1.3 was
   reworded with the full degrade shape and the fix landed perfectly. *Same species as this repo's
   recorded qwen3.6-35b "auditor-induced fabrication".*
2. **Unsatisfiable exit criteria.** Round 2 demanded "hardcode VCPU/RAM must fail" while also
   prescribing "assert VCPU==1, RAM==32" — but vcsim gives *every* VM exactly 1 vCPU / 32 MB, so the
   correct value **is** the hardcode. Similarly "transport → always unknown must fail" when correct
   code prints `unknown`. Withdrawn in round 3; one equivalent (criterion 9) still slipped through.
3. **HITLIST-round3 self-contradiction.** §0 said don't regress `net.JoinHostPort` while §3 ordered
   replacing the block containing it with `soap.ParseURL`. Resolution accepted: §3 supersedes.

**Lesson for round 4:** any bar you set must be satisfiable against vcsim's actual ground truth.

## Environment landmines

- **`go run github.com/vmware/govmomi/vcsim` does not exist at govmomi v0.55.1** — vcsim is a
  separate module. Use `go get github.com/vmware/govmomi/vcsim` in a scratch module, or in-process
  `simulator.VPX()` + `Model.Service.NewServer()`. The eval spec's line 196 is stale; recorded as a
  spec defect, not a model failure.
- **vcsim ground truth** (memorise — it decides fabrication calls): all datastores are
  `LocalDatastoreInfo`; HBAs are parallel-SCSI/block with `StorageProtocol=""`; `NvmeTopology=nil`;
  DVS reports `lacpApiVersion=""`, no uplink portgroup. **A correct implementation therefore prints
  `unknown` for every datastore and `N/A` for distributed LACP.** Unchanged output is the *expected*
  result of a correct fix; FC/iSCSI/NVMe appearing there is **fabrication**.
- **LM Studio TTL.** JIT-loaded models get a default **1h idle TTL** regardless of the per-model UI
  setting (`uiTTL.enabled: false` does not prevent it). An unload cost a 31-minute cold prefill.
  Load explicitly and omit `--ttl`:
  `lms load poolside/laguna-s-2.1 --context-length 262144 --parallel 1 -y` → `lms ps` TTL column blank.
- **A reload silently resets Enable Thinking.** It is not persisted to disk; it lives with the loaded
  instance and reverted to off once already. Run `laguna-s-2.1/check-thinking.sh` (prints
  `THINKING ON`/`THINKING OFF`) after any reload and before any round.
- **Prefill collapses with context**: 415 tok/s at 11k → 68 tok/s at 128k (12 full-attention layers
  make prefill quadratic). Keep instrument documents small; a 128k cold prompt costs ~31 min before
  the first token.
- **opencode ignores `limit.output`** and sends `max_tokens: 32000` on every request — a harness
  constant applied uniformly across the cohort, so it does not distort comparisons.
- **Streaming omits `reasoning_tokens`.** opencode's `tokens_reasoning` reads ~0 for laguna. This is
  an accounting artifact, **not** evidence the model doesn't reason — `reasoning_content` is
  non-empty in essentially every logged response. Do not repeat this misread.
- **`timeout` is not on macOS** (`gtimeout` or none). **`lms ps` output gets truncated by `sed -n '2p'`**
  — read enough lines or you will wrongly conclude no model is loaded.
- **Session forensics:** `~/.local/share/opencode/opencode.db` (`session`, `message`, `part` tables;
  `part.data` is JSON — use `json_extract`). LM Studio server logs at
  `~/.lmstudio/server-logs/YYYY-MM/`.

## Conventions to preserve

- **Never patch a self-authored remediation prompt.** Gaps are signal; the prompt becomes part of
  the post-run rubric. Capture it verbatim from the session store into
  `REMEDIATION-round<N>-prompt.md` with a provenance header (see rounds 1 and 3 for the format).
- **Commit the instrument before the round it drives** — matches gemma-4-31b and ornith-397B.
- **Branch per round**, so every boundary has a clean diff: `34b0138` (baseline), `6f73675` (r1),
  `5c6c082` (pre-r2), `b05c993` (r2), `4ce2cae`/`211fca6` (pre-r3), `4252de1` (r3). The
  round-1 evidence-forgery finding was only *establishable* because of these.
- **README records baselines**; arcs live in per-model "Remediation experiment" sections. The spine
  ledger carries the *latest* score. Don't sync them — they answer different questions.
- **The document trail in the workspace is deliberate.** Seven audit documents sit next to the
  submission and the model reads them unprompted. Confirmed intentional: the operator names the
  current instrument explicitly and leaves the rest, because that is what their repos look like.
  It is ecological validity, not contamination. **But `HITLIST-round2.md` is a hazard** — superseded,
  and still carrying the wording that induced the criterion-7 regression.
- **Disclose auditor contamination.** A reviewer left a stray `main.go` vcsim harness in the
  workspace root after round 3; it was removed and recorded rather than quietly deleted.
